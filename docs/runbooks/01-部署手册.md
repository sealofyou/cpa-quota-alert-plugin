# 01 - 部署手册

## 当前阶段

当前仓库处于 pre-alpha scaffold 阶段，没有可部署 `.so`。release workflow 只保留 tag 触发入口和结构检查，真实构建步骤在 ABI 实现完成后补齐。

## v0.1 预期部署顺序

1. 从可信源码或 GitHub release 获取 Linux amd64 `.so`。
2. 校验 SHA-256 checksum。
3. 在隔离 CPA `v7.2.83` 实例中加载插件，使用 dummy Management Key 和 dummy Codex auth。
4. 通过 loopback mock quota server 验证正常、低额度、恢复、partial、连续三次失败、未知套餐和 stale status。
5. 在生产 CPA 上先启用 `dry_run=true`。
6. 连续三轮与旧监控一致后，调用 `test-notification`。
7. 用户确认测试通知后，再切换真实通知。

## 回滚

1. 停止触发插件检查的 systemd timer。
2. 禁用插件配置。
3. 如热加载无效，恢复备份配置并受控重启 CPA。
4. 确认 CPA 核心请求恢复。
5. 保留失败 `.so` 的 SHA 与脱敏日志用于排查。

回滚不删除、不禁用、不刷新任何 CPA auth，不改变账号套餐，也不升级或降级 CPA。
