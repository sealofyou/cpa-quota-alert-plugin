# 02 - 运维手册

## 观测项

- CPA 进程健康
- systemd timer 是否按 5 分钟触发
- Management `check` 返回状态
- Management `status` 中的最近可信额度、stale、pending event 和通道健康
- CPA request log 是否开启，以及是否按短周期轮转并限制 root 可读
- 通知通道送达状态

## 常见风险

- `wham/usage` 响应结构变化
- `Chatgpt-Account-Id` 可能进入 CPA request log
- 单账号 401 或凭据错误被误判为整池失败
- 未知套餐被误算为零或默认权重
- pending event 因通知通道失败而重复发送
- 插件 panic 影响 CPA 进程稳定性

## 运维原则

- 不在公开文档、状态文件或日志中记录真实凭据和完整上游响应
- 不让插件接收或保存 CPA Management Key
- 套餐规则、终态错误和通知配置均由运维者显式配置
- 任何生产切换都先 dry-run，再人工确认测试通知
